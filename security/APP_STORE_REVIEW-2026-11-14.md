# Havana App Store compliance audit — 2026-11-14

Read-only source audit by Codex for Claude and the project owner. Baseline: local HEAD `37bd12a` plus working tree; CONVERSATION.md already had an uncommitted entry, preserved. Read HANDOFF.md and latest CONVERSATION.md first. No application code changed, no commit/push, no production writes, no credentials included.

**Verdict: not ready to submit.** The largest concrete gaps are UGC safeguards, reviewer access, privacy/support discoverability and inaccurate privacy/deletion claims. Havana has substantial marketplace functionality; its use of React Native or AI assistance is not itself evidence of low quality or a rejection reason. Approval remains Apple's decision.

Pass = source supports this requirement; Gap = missing or contradictory implementation/material; Risk = operational or binary/device evidence still needed. A source Pass does not certify the uploaded binary or console configuration.

## Scope and verification limits

Inspected mobile routes, shared UI/session/API/notification code, Expo/build configuration and store instructions; backend auth, market, chat, moderation, account deletion, privacy, photos, push, DTO/schema and deployment configuration. Targeted searches found no custom remote-code execution mechanism. Did not build, launch, change configuration, run authenticated probes or inspect App Store Connect/Play Console. No fresh iPhone/iPad acceptance or artifact-to-source provenance established. Live GET attempts to health/auth-methods/privacy failed through web tooling; local curl failed DNS resolution. That is an audit-environment limitation, not proof the API is down. The November 12 methods=false/false and health=200 results are historical, not today's status.

Policy basis: [Apple App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) checked today. The following findings are principally observations of this repository, with guideline numbers identifying the review area.

## Reviewer-visible unfinished details

- Login may offer no working method until a real provider is configured; “Phone login is coming soon” (`login.tsx:105`, `backup.tsx:50`) reads as unfinished when metadata promises phone login. Advertise only available methods; hide unavailable-method teaser text for submission if phone delivery is deferred.
- Development-code branches and the missing-API laptop setup instruction are release polish hazards, even if current production guards keep them unreachable in a correctly configured build.
- Support placeholder/circular contact text, missing policy/community links, Accra-only permission text and deletion overclaims are concrete unfinished details, not aesthetic opinions.
- Notifications silently skip without EAS projectId (`mobile/src/notifications.ts:49–56`); app.json has no projectId. Configure and device-test push credentials if shipping/advertising notifications; current chat polling does not prove background delivery.
- Browse searches/sorts only the newest 500 matching records (`backend/src/market.ts:67–78`, API_CONTRACT.md). Avoid claiming exhaustive inventory beyond that window; full-set pagination is the smallest correctness fix when needed. It need not block a small genuine launch inventory.
- `backend/prisma/seed.ts` creates demo inventory using external stock photos. Historical handoff records production seeding, but current inventory was not inspected. Remove stale/fake listings or clearly segregate review fixtures; ensure legitimate image rights and never misrepresent seeded sellers as real active supply.
- iOS signing/archive/TestFlight evidence and fresh native visual QA are absent in this audit. Existing Android and browser acceptance cannot certify iPhone layout. `mobile/plugins/withReleaseSigning.js` is Android-specific and permits debug-key fallback when signing files are absent: verify the Play artifact uses the intended upload certificate, not a preview build.

## Release order

1. Complete filtering, block/report-user/chat abuse controls, monitored support and moderation staffing.
2. Enable genuine login delivery, always-on backend and independently usable review access; remove stale dev-login instructions.
3. Align stored data/deletion behavior with policies, expose privacy/support in-app, finish Apple/Google privacy and age questionnaires and export declaration.
4. Test exact signed iOS/Android builds, safe areas/keyboard/iPad compatibility, core two-user trades, deletion and push; capture accurate native screenshots and review notes. Fix observed failures before submission.
