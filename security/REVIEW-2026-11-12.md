# Havana security review — 12 November 2026

Scope: current backend/mobile source, deployment/build configuration, npm production dependency audits, read-only live endpoint checks and a harmless local image-decoder probe. This is not a penetration test or confirmation of production dependency versions. No production accounts, login challenges or content were created. No implementation or deployment settings changed.

## Findings in priority order

1. **Critical configuration risk: public development OTP (SEC-004).** render.yaml explicitly enables DEV_OTP and ALLOW_DEV_OTP_IN_PRODUCTION. backend/src/auth.ts request() returns devCode and verify() accepts it for existing identities. Thus anyone able to request a code for another identity can authenticate as that identity when this mode is deployed. The admin trusted-session guard limits moderator escalation, but does not protect normal users, chats, listings or account deletion. Prior Claude deployment evidence records dev mode enabled; today's GET /auth/methods returns both true, which is consistent with but does not independently prove dev mode. Do not treat that endpoint as a flag-disclosure API. Required: configure real delivery, disable both development flags in the deployment and blueprint, verify delivery and no devCode, and invalidate existing dev-issued sessions. Removing dev flags alone does not invalidate 30-day dev JWTs; rotate signing credentials with a planned all-user re-login or implement session revocation.

2. **High: vulnerable request and image parsing dependencies (SEC-005).** Local body-parser 2.3.0 is affected by an unauthenticated compressed-request process-crash advisory; Nest initializes default parsing before route guards. Sharp 0.34.5 is affected by multiple decoder advisories, including conditional Linux RCE in SVG decoding. The upload filter only checks caller-controlled MIME. A benign SVG passed to the existing compiled encodePhoto function decoded successfully (68-byte WebP). This establishes decoder reachability, not exploitation or the precise conditions on Render. Upgrade to patched compatible dependencies, verify deployed lock/install, and reject formats other than JPEG/PNG/WebP based on decoded metadata or block unused loaders before decoding. Do not send crash payloads to production.

   Sources: https://github.com/advisories/GHSA-27r3-jxmh-p828 (body-parser >=2.4.0); https://github.com/advisories/GHSA-wq5f-xc86-pv6w (Sharp >=0.35.5, or block SVG loader); additional entries preserved in backend-audit.json. npm reports Multer too, but the listed async-fileFilter precondition is not established for this app's synchronous filter. Prisma/config findings require separate migration/tooling reachability triage.

3. **Medium: logout does not revoke server sessions (SEC-006).** backend/src/app.ts signs JWTs for 30 days; Guard verifies signature/expiration and deletedAt only. mobile/src/session.tsx removes the local token on logout, without a server revocation call. A previously copied token remains accepted until expiry or account deletion. Add per-session identifiers/revocation and a revoke-session endpoint; support offline local logout without blocking, with explicit limits on offline revocation. Code-confirmed design gap, not a live replay test.

4. **Medium release risk: debug signing / cleartext permitted (SEC-007).** Generated android/app/build.gradle release uses signingConfigs.debug; Android manifest and app.json enable cleartext traffic. These are preview defaults, not release protection. Use a private production signing identity and disable cleartext in production while retaining local development settings as needed. Hosted API URL is HTTPS, so no plaintext credential transmission was observed. Existing public APK certificate was not independently re-inspected in this pass; prior build notes identify development signing.

## Protections observed

Chat endpoints check conversation membership; listing changes check owner identity; listing photos must belong to the uploader. OTPs have a five-minute expiry, five incorrect-attempt limit, keyed hashes, serializable verification and replay deletion. Moderator access requires real-channel session trust plus an allowed email. Non-owner coordinates are scrubbed and distance calculations use grid cells. Native tokens use SecureStore. No tracked environment secrets or private-key files were found by filename inventory (not a full secret/history scan).
